# GitHub governance

GitHub is the engineering source of truth once a remote repository is selected. For each milestone: create an issue with measurable acceptance criteria, develop on a descriptive branch, use conventional commits, open a pull request with tests/risks/screenshots, and update this status document after review.

Suggested initial issue titles:

1. `docs: complete milestone 0 provider and brand discovery`
2. `feat(api): add persistent identity and role authorization`
3. `feat(catalog): add merchants, products and inventory`
4. `feat(orders): add transactional quote and lifecycle`

Do not include secrets, real customer data, provider credentials, or identity documents in issues, commits, screenshots, or fixtures.
